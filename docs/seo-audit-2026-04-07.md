# SEO Audit: kaderos.io
**Datum:** 7. April 2026
**Scope:** Code-Analyse `/apps/web/`
**Status:** Nur Analyse, keine Code-Änderungen

---

## Executive Summary

kaderos.io hat eine solide SEO-Grundstruktur (Metadata, Sitemap, robots.txt, JSON-LD). Es gibt aber **kritische Lücken**, die das Ranking-Potenzial massiv einschränken:

1. **14 Blog-Artikel fehlen in der Sitemap** (nur 18 von 32 indexiert)
2. **Homepage ist komplett `"use client"`** -- kein Server-Side Rendering der wichtigsten Seite
3. **Keine hreflang Tags** für de-CH Targeting
4. **Keine internen Links zwischen Blog-Artikeln** (0 Cross-Links gefunden)
5. **Keine Bilder** (kein `next/image`, keine `<img>` Tags, keine Alt-Tags)
6. **Kein JSON-LD in Blog-Artikeln** (nur im Root Layout)
7. **Umlaute-Verstösse** im Code ("Zuerich", "Menue oeffnen")

**Geschätzte SEO-Verbesserung bei Umsetzung aller Empfehlungen: 40-60% mehr organischer Traffic innerhalb von 3 Monaten.**

### 1.2 robots.ts

**Status: GUT, aber unvollständig**

```
Disallow: /api/
```

Fehlende Disallows:
- `/dashboard/` -- ist zwar auth-geschützt, aber Crawlern trotzdem verbieten
- `/onboarding/` -- gleiche Situation
- `/login/` -- kein SEO-Wert
- `/signup/` -- kein SEO-Wert
- `/forgot-password/` -- kein SEO-Wert
- `/reset-password/` -- kein SEO-Wert

**Empfehlung:** Alle App-Routes (auth, dashboard, onboarding) explizit in robots.ts disallow-Listen aufnehmen.

### 1.3 Metadata

**Status: GUT**

Alle Seiten haben `export const metadata` mit `title` und `description`:
- Root Layout: Template-basierter Title (`%s | KaderOS`) -- korrekt
- Alle 32 Blog-Artikel: Individuelle title + description -- korrekt
- Statische Seiten (Features, Pricing, Templates, etc.): Alle haben Metadata -- korrekt
- OpenGraph + Twitter Cards im Root Layout: Korrekt konfiguriert

**Problem 1: Enterprise-Seite hat KEINE Metadata** (ist `"use client"` ohne Server Component Wrapper)

**Problem 2: Canonical URL** nur im Root Layout gesetzt (`https://kaderos.io`). Keine seitenspezifischen Canonicals. Blog-Artikel brauchen eigene Canonical URLs um Duplicate Content zu vermeiden.

**Empfehlung:**
- Enterprise-Seite: Server Component mit Metadata erstellen, Client-Code in separate Datei auslagern
- Canonical URLs pro Seite setzen (alternates.canonical in jeder page.tsx Metadata)

### 1.4 Structured Data / JSON-LD

**Status: TEILWEISE**

Das Root Layout enthält gutes JSON-LD mit:
- `Organization` (Name, URL, Logo, Adresse Zürich, CH)
- `WebSite` mit SearchAction
- `SoftwareApplication` mit 4 Pricing Offers (Community, Pro, Team, Agency)

**Fehlend:**
- **Kein `Article` JSON-LD** in den 32 Blog-Artikeln (Headline, Author, DatePublished, etc.)
- **Kein `BreadcrumbList`** JSON-LD
- **Kein `FAQPage`** JSON-LD auf relevanten Seiten

**Empfehlung:** BlogPosting-Schema in jeden Blog-Artikel einfügen. Das bringt Rich Snippets in den SERPs.

### 1.5 Next.js Image Optimization

**Status: KRITISCH**

**Es werden KEINE Bilder verwendet.** Weder `next/image` noch `<img>` Tags existieren im gesamten Marketing-Bereich. Die Website ist rein text-basiert.

**SEO-Impact:**
- Keine Bilder in Google Image Search
- Keine visuellen Rich Snippets möglich
- Höhere Bounce Rate bei reinen Text-Seiten
- Blog-Artikel ohne Hero Images ranken schlechter

**Empfehlung:** Mindestens Hero-Images für Blog-Artikel und Feature-Screenshots hinzufügen. `next/image` mit Alt-Tags verwenden.

### 1.6 Client-Side Rendering

**Status: KRITISCH**

`"use client"` Dateien im Marketing-Bereich:

| Datei | Problem |
|-------|---------|
| `(marketing)/page.tsx` | **Homepage ist komplett CSR** -- Google kriegt leeren Container |
| `(marketing)/layout.tsx` | Navbar/Footer sind CSR (weniger kritisch) |
| `(marketing)/enterprise/page.tsx` | **Keine Metadata möglich wegen "use client"** |
| `blog/blog-client.tsx` | Blog-Index ist CSR (Blog-Listing nicht SSR) |
| `features/features-client.tsx` | OK -- Client Component wird in Server Component importiert |
| `pricing/pricing-client.tsx` | OK -- gleiche Struktur |
| `templates/templates-client.tsx` | OK -- gleiche Struktur |
| `changelog/changelog-client.tsx` | OK -- gleiche Struktur |

**Kritische Probleme:**
1. Die **Homepage** (`page.tsx`) beginnt mit `"use client"` -- der gesamte Content wird clientseitig gerendert. Google rendert JavaScript, aber mit Verzögerung. Die wichtigste Seite der Website ist damit im SSR-Index potenziell leer.
2. **Enterprise-Seite** ist `"use client"` direkt in page.tsx -- daher kann kein `export const metadata` gesetzt werden. Next.js ignoriert Metadata-Exports in Client Components.

**Empfehlung:**
- Homepage: Server Component erstellen, interaktive Teile (WaitlistForm, AnimNum, PlatformTabs) als separate Client Components importieren
- Enterprise: Gleiche Refactoring-Strategie -- Server page.tsx mit Metadata, Client Component für UI

## 2. On-Page SEO

- Enterprise hat `<h1>`
- Features, Pricing, Templates: H1 in Client Components vorhanden
- Not-Found-Seite hat `<h1>`

**Fehlend:** Keine Info ob Impressum, Datenschutz, AGB eigene H1 haben (müsste geprüft werden in den Client Components).

### 2.2 Interne Verlinkung zwischen Blog-Artikeln

**Status: KRITISCH**

**0 (null) interne Links zwischen Blog-Artikeln gefunden.** Kein einziger Blog-Artikel verlinkt auf einen anderen Blog-Artikel. Das ist ein massives SEO-Problem:
- Google kann die thematische Cluster-Struktur nicht erkennen
- Kein PageRank-Flow zwischen Artikeln
- Nutzer bleiben nicht auf der Seite

**Empfehlung:**
- Jeder Artikel sollte 2-3 Related Posts am Ende haben
- Im Fliesstext auf thematisch verwandte Artikel verlinken
- Topic Clusters bilden (z.B. "nDSG"-Cluster mit 3 Artikeln, "Kosten"-Cluster mit 3 Artikeln)

**Vorgeschlagene Cluster:**
1. **nDSG/Compliance:** ndsg-ai-konform, ndsg-ai-compliance, ndsg-ai-schweiz, ai-governance-kmu, ai-risiken-kmu
2. **Kosten/Budget:** ai-kosten-kmu, ai-budget-planen, ai-agent-kosten
3. **Vergleiche:** crewai-vs-kaderos, kaderos-vs-crewai-n8n, paperclip-vs-kaderos, ai-agent-vs-chatbot
4. **Solo Founders:** solo-founder-ai-stack, solo-founder-ai-team
5. **AI Agents Schweiz:** ai-agents-schweiz, ai-agents-schweiz-2026, ai-fuer-kmu-schweiz, schweizer-startups-ai

### 2.3 Alt-Tags auf Bildern

**Status: N/A**

Keine Bilder vorhanden, daher keine Alt-Tags nötig. Wird relevant sobald Bilder hinzugefügt werden.

### 2.4 URL-Struktur

**Status: GUT**

- Blog: `/blog/{slug}` -- sauber, deutsch, keyword-rich
- Statische Seiten: `/features`, `/pricing`, `/templates` -- klar
- Keine unnötigen Parameter oder IDs in URLs
- Deutsche Slugs mit korrekten Bindestrich-Trennungen

### 2.5 Canonical URLs

**Status: MANGELHAFT**

Nur die Root-URL hat eine Canonical (`https://kaderos.io`). Keine einzige Unterseite hat eine eigene Canonical URL definiert.

**Empfehlung:** In jeder page.tsx Metadata-Export Canonical hinzufügen:
```ts

```

## 4. Swiss/DACH SEO

### 4.1 hreflang Tags

**Status: FEHLEND**

Keine hreflang Tags vorhanden. Das `<html lang="de-CH">` ist korrekt gesetzt, aber hreflang im `<head>` fehlt.

**Empfehlung:** Im Root Layout oder per Metadata:
```ts
alternates: {
  languages: {
    'de-CH': 'https://kaderos.io',
    'de': 'https://kaderos.io',
  }
}
```

Dies signalisiert Google, dass die Seite für den Schweizer Markt gedacht ist, aber auch für deutschsprachige Nutzer allgemein relevant.

### 4.2 Lokale Keywords

**Status: GUT**

Schweiz-spezifische Keywords sind gut integriert:
- "Schweizer KMU", "Swiss Made", "nDSG", "CHF"
- Städte-Referenzen: "Zürich", "Lausanne", "Ostschweiz"
- Branchenspezifisch: "Bexio", "Treuhand"

**Fehlend:**
- Google My Business Eintrag (nicht im Code sichtbar, aber empfohlen)
- "Schweiz" im Title der Homepage wäre hilfreich
- Lokale Schema.org `address` ist korrekt gesetzt (Zürich, CH)

### 4.3 .io Domain SEO-Auswirkungen

**.io ist kein Country-Code-TLD** -- Google behandelt .io als generische TLD (gTLD). Das bedeutet:
- Kein inhärenter Geo-Vorteil für die Schweiz
- Google Search Console: Geo-Targeting muss manuell auf Schweiz gesetzt werden
- Kein Nachteil gegenüber .ch, aber auch kein Vorteil
- .io wird in der Tech-Szene gut akzeptiert und vertraut

**Empfehlung:** In der Google Search Console das Targeting auf "Schweiz" setzen (falls noch nicht geschehen). Long-term: Eine .ch Domain als Redirect oder Alias erwägen.

### 4.4 Umlaute-Verstösse

**ACHTUNG: Brand-Regel verletzt!**

Im Marketing Layout (`layout.tsx`) gefunden:
- Zeile 52: `"Menue oeffnen"` und `"Menue schliessen"` (aria-labels)
- Zeile 132: `"Zuerich, Schweiz"` (Footer)

Gemäss Brand Guide und Memory-Regeln: **IMMER ä ö ü, NIEMALS ae oe ue.**

**Korrektur nötig:**
- `"Menue oeffnen"` -> `"Menü öffnen"`
- `"Menue schliessen"` -> `"Menü schliessen"`
- `"Zuerich, Schweiz"` -> `"Zürich, Schweiz"`
